# Что нужно сделать вам, прежде чем я создам сервер (IB-013)

Простыми словами и по шагам. Всё делается один раз, занимает 10–15 минут.
После последнего шага я смогу создавать ресурсы в AWS — до этого я не трогаю ничего.

Итог по деньгам: **≈ 13.6 $ в месяц** при вашем потолке 20 $. Построчно — в
[`COST-PLAN.md`](COST-PLAN.md). Плюс я включу автоматическое предупреждение на почту,
если расход за месяц превысит 18 $.

## Шаг 1. Создать пользователя для развёртывания

1. Войдите в консоль AWS под своей основной учётной записью.
2. Откройте **IAM** → слева **Users** → кнопка **Create user**.
3. Имя: `insight-bot-provisioner`. Галочку «Provide user access to the AWS Management Console»
   **не ставьте** — этому пользователю консоль не нужна.
4. Нажмите **Next**.

## Шаг 2. Выдать ему только нужные права

1. На экране прав выберите **Attach policies directly** → **Create policy** (откроется новая вкладка).
2. Там переключитесь на вкладку **JSON** и вставьте содержимое файла
   [`iam/provisioner-policy.json`](iam/provisioner-policy.json) из репозитория, заменив то, что было.
3. **Next** → имя политики: `insight-bot-provisioner` → **Create policy**.
4. Вернитесь на вкладку с созданием пользователя, нажмите обновить список политик,
   найдите `insight-bot-provisioner`, поставьте галочку → **Next** → **Create user**.

> **Если вы уже создавали эту политику раньше (до 2026-10-07) — её нужно обновить один раз.**
>
> В файле были две ошибки. Первую вы уже исправили руками в консоли: у сервиса Budgets нет
> действий `DescribeBudgets`, `CreateBudget` и `DeleteBudget` — есть только `ViewBudget` (чтение)
> и `ModifyBudget` (создание, изменение и удаление). Теперь то же самое записано и в файле, так
> что консоль и репозиторий больше не расходятся.
>
> Вторую ошибку вы бы увидели позже и уже на шаге `terraform plan`: при чтении бакета AWS
> запрашивает ещё десяток мелких настроек (политика, ACL, CORS, логирование и другие), и прав на
> них в файле не было — вышло бы `AccessDenied` и политику пришлось бы править ещё раз. Эти права
> добавлены, по-прежнему только для нашего бакета.
>
> Что сделать: **IAM → Policies → `insight-bot-provisioner` → Edit → вкладка JSON → заменить всё
> содержимое** текущим файлом [`iam/provisioner-policy.json`](iam/provisioner-policy.json) →
> **Next** → **Save changes**. Пользователя и ключи трогать не нужно: политика у него уже
> привязана, меняется только её содержимое.
>
> Все 98 действий в файле сверены со справочником AWS (Service Authorization Reference),
> несуществующих среди них нет.

> ### Обновление от 2026-10-07, вечер: нужна ещё одна — последняя — вставка. Извините.
>
> Это третий раз, когда мы просим вас вставить эту политику, и причина — наша ошибка, а не ваша.
> Запуск `tofu apply` создал 5 ресурсов из 12 и остановился на двух отказах:
>
> 1. **Не хватало права `budgets:TagResource`.** Мы помечаем все ресурсы тремя метками
>    (`Project`, `ManagedBy`, `Component`), чтобы в счёте было видно, что именно тратит деньги.
>    Метки задаются один раз на весь проект, в другом файле, — поэтому, проверяя политику, мы
>    просто не увидели, что лимит бюджета тоже помечается, а на пометку бюджета в AWS нужно
>    отдельное право. Добавлено, вместе с двумя парными правами (снять метку, прочитать метки),
>    чтобы это не всплыло при следующем изменении.
> 2. **Право `s3:GetBucketPolicy` в файле уже есть** — значит, в консоли сейчас лежит версия
>    политики старше файла: предыдущая вставка либо не сохранилась, либо была сделана до
>    исправления. Сама вставка это и вылечит.
>
> Что сделать — ровно то же, что и раньше: **IAM → Policies → `insight-bot-provisioner` → Edit →
> вкладка JSON → заменить всё содержимое** текущим файлом
> [`iam/provisioner-policy.json`](iam/provisioner-policy.json) → **Next** → **Save changes**.
>
> **Ничего из созданного не пропало и ничего не тратит деньги.** Роль, группа безопасности,
> профиль и бакет уже существуют и записаны в состоянии; повторный запуск просто досоздаёт
> остальное. Сервер пока не создан.
>
> Честно о том, почему мы не обещаем, что это точно последний раз: сверка со справочником
> доказывает, что действие **существует**, но не доказывает, что список **полный**. Полноту
> показывает только реальный запуск — именно он и показал.

Что эта политика разрешает и чего не разрешает:

- можно: создавать сервер, диск, группу безопасности **только в регионе Токио**;
- можно: создать **один** бакет `vb-insight-bot-backups-apne1` и писать в него;
- можно: читать и записывать параметры только с именами `/insight-bot/*`;
- можно: создать роль **только** с именем `insight-bot-instance` для самого сервера;
- можно: создать бюджет с именем `insight-bot-monthly`;
- **нельзя**: трогать что-либо в других регионах, другие бакеты, других пользователей,
  выдавать себе новые права, работать с биллингом сверх одного бюджета.

## Шаг 3. Создать ключ доступа

1. Откройте созданного пользователя → вкладка **Security credentials**.
2. **Access keys** → **Create access key**.
3. Тип: **Command Line Interface (CLI)**, внизу подтвердите галочкой и **Next** → **Create access key**.
4. На экране будут **Access key ID** и **Secret access key**. Секрет показывается **один раз** —
   держите вкладку открытой до следующего шага (или скачайте .csv).

**Эти ключи нигде не публикуйте и не присылайте мне.** Я их не вижу и не должен видеть: я работаю
через профиль, который вы сейчас настроите, и печатать их никогда не буду.

## Шаг 4. Настроить профиль на своей машине

**Сначала проверьте, установлен ли AWS CLI** — на машине, где я работаю, его сейчас нет:

```
aws --version
```

Если команда не найдена, установите (macOS):

```
brew install awscli
```

Затем выполните:

```
aws configure --profile insight-bot
```

Команда задаст четыре вопроса:

| Вопрос | Что ввести |
|---|---|
| `AWS Access Key ID` | ключ из шага 3 |
| `AWS Secret Access Key` | секрет из шага 3 |
| `Default region name` | `ap-northeast-1` |
| `Default output format` | `json` |

Проверить, что всё записалось (эта команда не показывает секрет):

```
aws sts get-caller-identity --profile insight-bot
```

Должен вывестись ваш номер аккаунта и имя `insight-bot-provisioner`.

## Шаг 4. Поставить OpenTofu (одна команда)

Это последнее, что нужно от вас перед созданием сервера. Моя недоработка: в прошлой версии этой
инструкции шага не было — я написал «запускаю Terraform», но не сказал, что его сначала надо
поставить.

```bash
brew install opentofu
tofu version
```

Почему OpenTofu, а не Terraform: это тот же инструмент и те же файлы, но со свободной лицензией
(MPL-2.0). У Terraform с версии 1.5 лицензия BUSL — она накладывает ограничения, и решать, брать
ли их на себя, вам, а не мне. Наша конфигурация не использует ничего особенного, поэтому оба
подходят, и команда `tofu` ведёт себя как `terraform`.

Если вы предпочитаете Terraform — поставьте его (`brew install terraform`), и скажите мне: я
просто буду писать `terraform` вместо `tofu`, больше ничего не изменится.

(`tofu destroy`), бакет с копиями можно оставить — он стоит центы.
