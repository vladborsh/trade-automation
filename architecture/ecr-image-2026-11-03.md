# The image moves to ECR — design (2026-11-03)

**Author:** Architect (insight-bot stream) · **Input:** user ruling 2026-11-03 via the coordinator
(`reports/coordinator-ecr-2026-11-03.md`): the insight-bot image lives in ECR ap-northeast-1. The
GHCR package is **not** made public. · **Amends:** `infra/insight-bot/COST-PLAN.md` "Deploy path"
(ECR dropped for GHCR), `member-access-design-2026-10-31.md` M6. · **Output:** IB-083. **Timing:** IB-073's apply goes ahead WITHOUT ECR (Tech Lead). Everything here is additive, applied later on the running box, and never through `user_data` (E10).

## 1. Why the ruling holds up

The repository may go private once members pay. With ECR the box pulls with its **instance role**.
Nothing then depends on whether the repo or the package is visible, and no GitHub token sits in SSM
waiting to be rotated. ECR charges for stored GB only. A same-region pull is free.

## 2. Decisions

| # | Decision | Why |
|---|---|---|
| E1 | **One private ECR repository `insight-bot` in ap-northeast-1, managed by OpenTofu. Encryption AES256 (the default, no KMS charge). `force_delete = false`.** | One image, one region, same as the box. Tofu must not be able to drop the images the box runs from. |
| E2 | **Tags are IMMUTABLE. Images are tagged only `sha-<12-char commit>`. There is no `latest`.** The box deploys a named sha (E10). Rollback means deploying an older sha. | With immutable tags, a sha in a deploy log always means the same bytes. A mutable `latest` makes "what is running?" unanswerable after the fact. The cost: CI must skip the push when the tag already exists (rebuilding one commit twice), and `deploy.sh` must be given the tag. IB-BUG-016 already tags images by commit. |
| E3 | **Lifecycle policy:** (1) untagged images expire after 1 day; (2) only the newest **10** `sha-` images are kept. | Ten deploys back is enough rollback for a one-box product. Storage stays at most 10 images, with shared layers counted once. IB-083 reports the actual size, which nobody has measured yet. At $0.10/GB-month this is cents, not dollars. |
| E4 | **Basic scan-on-push is on. Findings are informational, not a deploy gate.** | Basic scanning costs nothing and puts the known-CVE list next to each sha. Making it a gate would block deploys on base-image CVEs we cannot fix the same day. That is not worth it before there are paying members. Revisit then. |
| E5 | **Instance role:** `ecr:GetAuthorizationToken` (AWS requires `*` for it) plus `ecr:BatchGetImage`, `ecr:GetDownloadUrlForLayer` and `ecr:BatchCheckLayerAvailability` on **that one repository's ARN**. `deploy.sh` logs in with `aws ecr get-login-password` on every deploy (the token lasts 12 h). The `GHCR_TOKEN`/`GHCR_USER` path and the SSM parameter `/insight-bot/GHCR_TOKEN` go away. | Pull only, one repository. AL2023 ships the AWS CLI, so nothing new is installed. |
| E6 | **Decided: CI deploy gets its identity NOW, in the ECR apply (not later):** the GitHub OIDC provider (`token.actions.githubusercontent.com`) and the role `insight-bot-deploy`. The trust is `repo:vladborsh/trade-automation:ref:refs/heads/master`, audience `sts.amazonaws.com`. The role may push to that one repository and run `ssm:SendCommand` on the instance (as now). If the account already has a GitHub OIDC provider, it is **imported**, not created a second time (only one is allowed per URL per account). | This is the one way to keep the owner at **one** paste. Both are free. Without the provider the workflow cannot push to ECR at all. The coordinator corrected the earlier claim to the user: the role does not exist today. |
| E7 | **First image now, by hand:** `infra/insight-bot/scripts/push-image.sh` (new). It does `aws ecr get-login-password` → `docker tag` → `docker push <repo>:sha-<commit>` from a locally built linux/arm64 image, using profile `insight-bot`. It refuses a dirty tree, and it refuses when the tag already exists (E2). dev-1 pushes `sha-69b2380` with it. | The box is not blocked on CI. The same script is also the fallback when Actions is unavailable (§3). |
| E8 | **CI (`insight-bot-deploy.yml`) pushes to ECR**: `aws-actions/configure-aws-credentials` (OIDC) → `aws-actions/amazon-ecr-login` → buildx linux/arm64 → push `sha-<commit>` unless it exists → SSM deploy of that tag. The `packages: write` permission and the GHCR login go. The trigger stays `workflow_dispatch` only, as now. | It was GHCR-first only so the build needed no AWS. With OIDC now present (E6), that reason is gone. |
| E9 | **GHCR clean-up after the first ECR deploy works:** the owner deletes the private package `ghcr.io/vladborsh/insight-bot` in GitHub. dev-1 does it only if `gh` has `delete:packages` (it most likely does not). Not urgent and not gating. | It is private, so leaving it costs nothing. Deleting it only removes confusion. |
| E10 | **The image reference is NOT in `aws_instance.user_data`.** It lives in the SSM parameter `/insight-bot/IMAGE_TAG` (String, not secret). `push-image.sh` and the CI job write it after a successful push. `deploy.sh` reads it from SSM, accepting an optional tag argument that overrides it, and refuses `latest` or an empty value. The repository URL comes from the account and region, not from the parameter. OpenTofu does **not** manage this parameter, because every deploy changes it and tofu would report drift. `user_data` stops writing `/opt/insight-bot/image-ref`, and the `image_ref` variable goes away. | Any change to `user_data` is an in-place `ModifyInstanceAttribute` on the running box, which needs a stop. A tag that changes on every deploy must never be one. With SSM, a rollback is: put the older tag, run deploy. The box can already read `/insight-bot/*`, and the deploy role gets `ssm:PutParameter` on this one parameter. (Tech Lead, 2026-11-03.) |

## 3. Builds off Actions? Not now

Today the repo is public and the workflow is manual. When the repo goes private:

- Actions minutes become metered.
- A QEMU arm64 build of this image is slow.

Two cheap ways out when that day comes:

- **(a) Build on the owner's machine** with E7's script. That is how the first image is made anyway.
- **(b) A native arm64 runner.** Check what GitHub offers private repos at that time (not verified now).

Nothing is decided until the repo actually goes private.

## 4. The one owner paste (IB-083 step 1: `iam/provisioner-policy.json`)

Everything foreseeable for IB-073, IB-082 and IB-083 goes in one file, so the owner pastes once. That includes the deploy role's `ssm:PutParameter` on `/insight-bot/IMAGE_TAG`, already covered by the existing `/insight-bot/*` statement. IB-082's actions are already
there (afeb86b). Added:

- **ECR manage, on `arn:aws:ecr:ap-northeast-1:*:repository/insight-bot`:**
  - `ecr:CreateRepository`, `DeleteRepository`, `DescribeRepositories`;
  - `PutLifecyclePolicy`, `GetLifecyclePolicy`, `DeleteLifecyclePolicy`;
  - `PutImageScanningConfiguration`, `PutImageTagMutability`;
  - **`TagResource`**, `UntagResource`, `ListTagsForResource` (default_tags: create-with-tags needs the tag action; the 2026-10-31 budgets lesson);
  - `GetRepositoryPolicy`.
- **ECR push for the first image, same resource:**
  - `ecr:BatchCheckLayerAvailability`, `InitiateLayerUpload`, `UploadLayerPart`, `CompleteLayerUpload`;
  - `PutImage`, `BatchGetImage`, `GetDownloadUrlForLayer`, `DescribeImages`, `ListImages`;
  - plus `ecr:GetAuthorizationToken` on `*`.
- **IAM, on the deploy role `arn:aws:iam::*:role/insight-bot-deploy`:** the same verbs the instance
  role has (Create/Delete/Get role, Put/Delete/Get role policy, TagRole, UpdateAssumeRolePolicy,
  ListRolePolicies, ListAttachedRolePolicies). No `PassRole`: nothing passes this role.
- **IAM, on `arn:aws:iam::*:oidc-provider/token.actions.githubusercontent.com`:**
  - `iam:CreateOpenIDConnectProvider`, `GetOpenIDConnectProvider`, `DeleteOpenIDConnectProvider`;
  - `TagOpenIDConnectProvider`, `UntagOpenIDConnectProvider`, `UpdateOpenIDConnectProviderThumbprint`;
  - plus `iam:ListOpenIDConnectProviders` in read-only discovery.
- **The instance role's new inline ECR statement** needs nothing new: `iam:PutRolePolicy` on
  `insight-bot-instance` is already allowed.

Policy validation cannot prove the policy is sufficient (the 2026-10-31 lesson). The check is a real
`tofu plan` + `apply` + push. After the paste, the coordinator's dry-run probe confirms it is live.

## 5. Cost

ECR storage at most ~10 images × the image size (to be measured) × $0.10/GB-month. That is cents. A
same-region pull is free, and so are basic scanning, the OIDC provider and the role. The total stays
≈ 16.5 USD/month.
